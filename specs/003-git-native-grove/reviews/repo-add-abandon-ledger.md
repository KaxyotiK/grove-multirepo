# Recoverable `repo add` abandonment: evidence

**Authority:** constitution 6.0.0 Principles IV–V; FR-024; CLI and JSON result contracts; V3OPS-07. **Frozen predecessor:** `885253fd1c86d7e605447446603b93056aec3f5e`.

The defect is a durable-state dead end: after an interrupted fetch and loss of the remote, `reconcile --operation` records `recoverable-intermediate` / `git-failed`, while `reconcile --abandon` refuses the record solely because its state is `recoverable`.

| Requirement | Status | Witness |
| --- | --- | --- |
| Eligible interrupted acquisitions close and release their alias | implemented:verified-local | V3OPS-07 real interrupted fetch, removed remote, abandon and add again |
| Only a matching, content-proven, empty, unregistered bare anchor is removed | implemented:verified-local | V3OPS-07 owned empty in default/custom layout; replacement directory and bare repository; identity-free and proof-free records; changed scaffold bytes and custom template retained |
| Additional content, refs and worktrees survive explicit close | implemented:verified-local | V3OPS-07 root and nested added files, native ref/worktree, and fetched ref before a later Git failure |
| Retained acquisition content is itemized without raw secret bytes in the record | implemented:verified-local | V3OPS-07 nested hook appears in `survivingArtifacts`; genesis stores bounded per-entry metadata/content hashes and expected config hash, never raw config, hook, template, or credential bytes |
| Running and unrelated recoverable operations remain ineligible | implemented:verified-local | V3OPS-07 negative controls for running, other kind and non-Git recoverable reason |
| Git failure offers exact resume and abandon remedies | implemented:verified-local | V3OPS-07 recovery result and blocked add error |

The red run used the exact predecessor source and the new test file, `tests/cli/repo-add-abandon.test.ts`; the run log and the archived baseline source were kept outside the repository. It reported 8 tests, 1 pass and 7 failures; each failing eligible case reached the old exit-5 `Cannot abandon operation ... its durable state is recoverable` refusal. The unaffected ineligible control passed. This is a behavioral red rather than a missing-command or missing-test failure.

The active spec, implementation plan, tasks and contracts agree: FR-024 admits only `repo add` with durable recoverable `git-failed` evidence; V3OPS-07 covers both release of the logical alias and preservation of physical Git/user artifacts. Existing V3OPS-02 remains the conflicting acquisition regression authority; historical scenario IDs were not renumbered.

Independent review of `4fa9bf2` invalidated the original empty-shell proof: a filename/type check allowed user edits inside Git's initialized `description`, `info/exclude`, `config`, `HEAD`, and hook samples to be deleted. It also found that a preserved nested file was missing from `survivingArtifacts`. Six scaffold-edit tests went red against that frozen head (6 failures, 8 passes in the 14-test focused run); a separate nested-hook witness went red (1 failure). The round-two correction hashed scaffold entry identities/metadata and file bytes after remote configuration. It required the default Git template, but its late snapshot could still adopt content inserted before remote configuration finished. The retention inventory descends into nested content and explicitly marks incomplete enumeration. Custom layout, custom template, legacy proof-free, and unchanged removable anchor controls passed in the 20-test focused run.

Independent review of `68dc579` paused `git remote add` after the real `git init`, wrote unique text to `description`, then caused a failed acquisition. The late proof included that text and abandon deleted it. Two new description/exclude witnesses failed on the exact frozen product before round-three source edits (2 tests, 0 pass, 2 fail; the red run log was kept outside the repository). The revised provenance begins with Grove's newly created anchor identity and a bounded initial snapshot matched against a separately initialized default-template Git scaffold. The durable genesis stores paths, filesystem identity/metadata and file hashes, plus the expected hash of Git's remote config transition. Direct and resumed remote-add steps can record a final cleanup proof only when every initial entry except the expected config/root metadata transition remains unchanged. A pre-existing anchor reached by crash recovery without genesis stays proof-free. Post-init and post-remote-add crash tests check user-edit retention and pristine cleanup.
