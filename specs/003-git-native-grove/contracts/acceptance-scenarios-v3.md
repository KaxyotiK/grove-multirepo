# Grove v3 Acceptance Scenarios

These scenarios supplement, and do not renumber or replace, the 180 scenarios in the v2 behavioral contract. Each ID must appear in an executable test title and map through the exact disposition/witness ledger to its required assertion evidence. The final traceability gate validates both contracts independently; ID presence alone is insufficient.

## Retired v3 scenarios

Removed with the behaviour they described. Recorded, not silently dropped, so a reader of an older revision can see where the row went.

Written as a list, not a table: `scripts/scenario-traceability.mjs` reads every row of a table headed `ID` as a live scenario, so a retired row in such a table would be re-adopted as a scenario still owing a witness. Tables with any other header are prose and are not read.

- **`V3MIG-01`** — retired 2026-08-23. Ruling ⑤ deletes the migration subsystem. There is no schema-1 migration to observe; a schema-1 workspace is refused by `V3VER-01` instead.
- **`V3MIG-02`** — retired 2026-08-23. As `V3MIG-01`, for schema 2.

## Stable v2 scenario dispositions under schema 3

The 180 inherited IDs are never renumbered. Unchanged scenarios retain their original expected result. The following groups have an approved schema-3 disposition that supersedes the ownership mechanism or topology named by the older row:

- `DISC-14`, `INIT-01`, `INIT-06`, and `INIT-07` use the compiled `repos/`, `trunks/`, `groves/`, and `archives/` roots. Init refuses nonempty roots, publishes config last, and retries safely from an empty scaffold without a rollback journal.
- `TREE-14`, `TREE-19`, `TREE-21`, and `TREE-24` retain the branch/ref outcomes but do not record provenance or release claims. Git worktree registration is the only occupied-branch authority.
- `PROC-05`, `PROC-08`, `PROC-09`, and `PROC-10` use atomic publication and forward operation records. Successfully created refs/worktrees survive interruption or later-target failure; reconcile resumes or reports them and abandon never compensates. `PROC-11` reclaims only Grove's operation lock, never Git state.
- `REPO-03` through `REPO-07`, `REPO-11` through `REPO-14`, `REPO-16`, `REPO-22`, `REPO-24`, `REPO-28`, and `REPO-29` follow unregister-only removal and the removal of `repo delete-branch`. Reachability no longer authorizes a Grove ref deletion; users delete branches with native Git.
- `REPO-08` uses the schema-3 capability boundary and native one-branch/one-worktree authority: linked trunk mutation is an exit-3 policy refusal, while Tree creation remains supported and an occupied branch is an exit-4 conflict. Both name the exact claimant path without raw Git leakage or mutation.
- `TRUNK-10` and `TRUNK-11` now require every linked-repository trunk mutation, including removal of the advisory preferred trunk, to refuse before mutation.
- `TRUNK-01`, `TRUNK-02`, and `TRUNK-09` retain the exact §5 readable trunk allocation. In particular, `repo add --name grove-cli --trunk main` creates a Git worktree at `trunks/main@grove-cli`; collision/truncation suffixes occur only when required and do not reintroduce a persisted trunk inventory.
- `ARCH-01` through `ARCH-29` retain their applicable loose-file, dirty-worktree, detached-commit, collision, archive, restore, and recovery protections, but every branch ref is retained. Provenance/claim and branch-reachability distinctions no longer authorize deletion; force may discard named working files only and cannot discard an unreachable detached commit.
- `FILE-01` through `FILE-06`, `CMD-06`, `CMD-09`, `CMD-12`, `ISO-01` through `ISO-04`, and the remaining unchanged IDs preserve their prior user-visible safety result. Their current witnesses use schema-3 result envelopes and observed Git identities.
- **`CMD-11` is `superseded`, not preserved** (ledger G-12): its exit code changed 2 → 3. An earlier revision of this bullet listed it among the preserved IDs, contradicting its own disposition in `reviews/prior-release-scenario-ledger.json`. **The ledger is authoritative**, and `tests/module/contract-consistency.test.ts` now fails on any such disagreement rather than relying on a reader noticing it.
